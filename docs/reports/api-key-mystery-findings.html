The loop you have been living in

Groq shows a key's full value exactly once, at creation. You cannot go back and re-copy an existing key. That fact plus the revocations produces the exact cycle you described:

1. Dev run shows "invalid key". The dev build reads the shared vault slot, which holds a key Groq has already revoked.
2. You cannot re-enter the old key because Groq will not show it again, so you create a new key in the Groq console. If the old ones get deleted or regenerated in the process, every app still holding them dies at that moment, including the installed one. That is the "it breaks the installed app too".
3. The new key works "temporarily". It is genuinely valid, and whichever app you typed it into works.
4. The save sometimes lands nowhere. Tonight at 20:15 a validated key save never reached your real vault. Any key entered into an app instance that an AI agent session launched can vanish this way, and the vault quietly keeps the dead key, restarting the loop at step 1.

What only you can check

Open console.groq.com and look at the API keys page and your email from Groq:

  • How many keys exist right now, and do their creation dates match today 16:57 and earlier? If keys you created are missing, something or someone deleted them.
  • Any email from Groq tonight about a key being disabled, detected as exposed, or your account being flagged? That would mean Groq is auto-revoking and we need to find the exposure.
  • Think back to tonight between 20:15 and 22:45: did you create, regenerate, or delete any key in the console? Regenerating or deleting is precisely what kills the copy the installed app still holds.

How to exit the loop right now

  • Create ONE new key in the Groq console. Do not delete or regenerate anything else while you do it.
  • Enter it in the installed new app's own settings window (open it from the tray icon), not in a dev instance that an agent session launched. That writes your real vault, and dev builds you launch yourself will inherit it automatically.
  • Decide the old Python app's fate. It dictated as recently as this morning, listens to the same hotkey, and keeps its own separate key copy that dies on every rotation. If you still want it, give it the same new key; if not, uninstall it from C:\Users\PC\AppData\Local\Programs\WhisperOSS and the confusion drops sharply.
  • Never type a key into an app window that I or Codex launched. Tonight's evidence shows such a save can pass validation and still land outside your real vault.
