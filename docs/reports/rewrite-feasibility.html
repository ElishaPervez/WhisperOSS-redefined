Can the whole app be rebuilt in Tauri + Rust?

Based on a full read of the old Python app — 8,152 lines across 19 files in src-reference\

YES — FEASIBLE

Every feature of the old app can be rebuilt in Tauri + Rust, with no blockers. Most of it maps onto mature, well-maintained Rust libraries. Two areas need hand-written Windows-level code (which the old app also hand-wrote, so this is expected), and one area — the animated overlay — is a from-scratch redesign rather than a translation, which is actually where the "genuinely exceptional GUI" goal gets won.

Context

What the app does today, from the user's chair

Hold Ctrlthen Win

Dictation

You hold the keys anywhere in Windows and speak. A small black pill appears near the bottom of the screen showing live audio bars. When you release, the pill says "Processing", and a moment later your words are typed into whatever app you were using, followed by a checkmark animation. A half-second of audio from before you pressed the keys is included, so the first word is never cut off. Optional AI cleanup can add punctuation, a "casual mode" can lowercase everything and convert spoken emoji names into real emoji, and a translation mode can output a different language.

Hold Winthen Ctrl

Quick Answer

Same keys, opposite press order. You ask a question out loud; the pill morphs into a scrolling "thinking" ticker, then expands into a black answer card with the response streaming in word by word, backed by live web search. If you had text selected in another app, that selection is silently read and used as context. The card auto-dismisses after 50 seconds or when you click "Seen". Nothing is pasted.

Hold Winthen Alt

Visual Search

You ask a question, release, then drag a box around any part of any monitor. The screenshot region plus your spoken question go to the AI, and the answer streams into the same card.

Background

Everything else

A settings window with frosted-glass blur and light/dark themes (mic picker, model pickers, toggles for every behavior above). A system-tray icon — closing the window hides the app, it keeps running. Starts with Windows. First-run welcome flow that validates your API key before letting you in. API keys live in Windows Credential Manager, not in a plain file.

The critical path

What happens between key-press and text appearing

This chain is the product. Its speed and reliability is what the user feels every single use.

Keys heldmic buffer is already running — recording starts instantly
→
Keys releasedaudio packaged in memory, no temp files
→
Cloud transcribeGroq Whisper turns speech into text
→
Optional AI cleanuppunctuation / casual / translate
→
Pasteclipboard swapped in, Ctrl+V sent, original clipboard restored
The paste step uses a clever trick worth preserving: the transcript is placed on the clipboard with three special Windows flags so it never shows up in your Win+V clipboard history and never syncs to the cloud clipboard, then your original clipboard contents are put back. Privacy-correct — and if the flags can't be set, the old app deliberately refuses to paste rather than leak. The rewrite should keep this exact behavior.
Port difficulty

Where the effort actually goes

Drop-in

A maintained Rust library already does exactly this
  • Settings file same JSON file, same location
  • API keys in Credential Manager same vault the old app uses
  • Start with Windows official Tauri plugin
  • System tray + menu built into Tauri
  • Frosted-glass / rounded window library makes the identical Windows calls
  • Groq + Gemini calls both are plain web APIs; streaming included. Dropping the Python SDKs loses nothing
  • Mic capture + device list standard Rust audio library
  • Multi-monitor screenshots existing library — and it handles mixed-DPI monitors, which the old app gets wrong

Custom Windows code

Hand-written, but the old app hand-wrote it too — ports nearly 1:1
  • Hold-to-talk hotkeys off-the-shelf hotkey tools only do "press once to toggle." "Hold two keys, order decides the mode, abort if Shift is down" needs our own low-level keyboard listener. Bonus: doing it properly kills the old app's 20×/second polling loop and its reach into another library's private internals
  • History-proof paste the three privacy clipboard flags have no library wrapper in any language — the raw Windows calls translate directly to Rust
  • Silent selection-grab the "read what the user has selected" trick (brief Ctrl+C, restore) ports as-is

Redesign, not translation

Biggest work item — and the biggest win
  • The animated overlay 2,215 lines of frame-by-frame hand-drawn animation (audio bars, morphing pill, heartbeat-to-checkmark, word-by-word streaming reveal). In Tauri this becomes a transparent click-through web window where CSS/canvas animation does in dozens of lines what Qt needed hundreds for — smoother, GPU-composited, and far easier to make beautiful
  • Settings window 2,046 lines, roughly 60% of which is styling and hand-painted toggle switches. Becomes ordinary HTML/CSS — massive shrink, and where the "exceptional GUI" goal lives
Why rewrite instead of patch

Real defects in the old app the rewrite erases by design

🔴
A network hiccup freezes the overlay forever. No request anywhere has a timeout, a retry, or a cancel button — if the transcription service stalls, the pill says "Processing" until you kill the app. controller.pyRewrite: every request gets a timeout, cancellation, and a visible error state — designed in from day one.
🔴
Slow internet = frozen launch. On startup the app fetches two model lists over the network before the UI becomes responsive — the code even contains a comment admitting it. controller.py:389Rewrite: UI appears instantly; network work happens behind it.
🔴
The two main hotkeys misfire by construction. Dictation and Quick Answer use the same physical keys, told apart only by which you pressed last — detected via an 85 ms guess-delay plus a polling thread checking key state 20× a second, because key-release events get lost. hotkey_manager.pyRewrite: a proper low-level listener sees every key-down and key-up directly — no polling, no guessing.
🟠
Opening Settings secretly restarts your microphone. Every time the settings window appears, the entire audio system is torn down and rebuilt just to refresh the device list. ui_main_window.py:1686Rewrite: device list refreshes without touching the live mic stream.
🟠
Copy something at the wrong moment and it's gone. After pasting, your original clipboard is restored on a 550 ms timer — a pure timing guess. Copy during that window and the restore overwrites it. controller.py:976Rewrite: restore is sequenced off the actual paste, not a stopwatch.
🟠
Audio uploads are 3× bigger than needed. Recordings upload at whatever rate the mic runs (usually 48 kHz) and the server downsamples them — tripling upload time on every dictation. audio_recorder.py:274Rewrite: downsample locally before upload — faster results on any connection.
🟠
Question-answering is likely broken out of the box. The default answer-mode model name doesn't appear to be a real model, so Quick Answer fails until the user manually picks another one. config_manager.pyRewrite: ship verified defaults, validate on first run.
🟡
Screen snipping is offset on mixed-DPI monitor setups. The region you drag and the region that's captured disagree when monitors have different scaling. ui_screen_snip.pyRewrite: the Rust screenshot library is DPI-aware.
🟡
Animation burns CPU while hidden. Several animation timers run continuously even when nothing is on screen, and the streaming card re-measures its layout up to ~50 times per frame. ui_visualizer.pyRewrite: browser compositor animates on the GPU and pauses when invisible.
On top of the bug fixes: a Tauri + Rust build launches in a fraction of the time (no Python interpreter or Qt runtime to load), idles at a fraction of the memory, and ships as a single small installer instead of a bundled Python environment. That directly serves all three goals — GUI, reliability, speed.
Proposed shape

How the rewrite splits the work

Everything the user feels as latency lives in Rust. Everything the user sees lives in web windows.

🦀 Rust core — the fast path

  • Low-level keyboard listener (hold-to-talk, press-order modes)
  • Always-on mic buffer + half-second pre-roll
  • Local downsampling + in-memory audio packaging
  • Groq / Gemini calls with timeouts, retry, streaming, cancel
  • History-proof clipboard paste + restore
  • Screenshots, settings file, key vault, autostart, tray
⇄events &
commands

🎨 Web windows — the beautiful part

  • Overlay: transparent, click-through, always-on-top — pill, bars, morphs, streaming answer card, all CSS/canvas on the GPU
  • Settings window: the exceptional GUI, in real HTML/CSS
  • Snip overlay: full-screen region picker
  • Onboarding flow
Two honest caveats. ① The transparent click-through overlay is well-trodden in Tauri but needs care — toggling "clicks pass through me" on and off (the answer card must be clickable, the pill must not be) is the one Tauri-specific thing to prototype early. ② The low-level keyboard listener carries the same antivirus-heuristic risk the old app already had — unchanged, not worsened.
Next step

Where this goes from here

Repo is initialized and src-reference\ is git-ignored (verified). The sensible next move is a product spec: walk through the feature list above and decide what to keep as-is, what to improve (there's room — e.g., configurable hotkeys, a proper error/retry UX, history of past dictations), and what to cut. Then a technical spec pinning down the Rust crates, the overlay window strategy, and the milestone order — with the click-through overlay prototyped first, since it's the only real unknown.
